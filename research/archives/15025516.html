【進化】GPT Image 2.5、「また画質が上がっただけ」←本命は“何度直しても元画像を壊しにくい編集”だった件ｗｗ

 

画像生成AIの新モデルが出た。

 

そう聞くと、だいたい想像するのはこれだ。

 

「はいはい。前より綺麗になったんでしょ」

 

解像感が上がった。光が自然になった。人物の顔が良くなった。文字も少しマシになった。

 

もちろんGPT Image 2.5にも、その手の改善はある。

 

OpenAIは2026年9月8日に発表したChatGPT Images 2.5について、より鮮明なディテール、自然な照明と質感、生成速度の向上を挙げている。Images 2.0と比べ、画像生成の待ち時間も最大50％短縮したという。

だが、今回かなり面白いのはそこではない。

 

「この画像いい。でも猫だけ直したい」

 

画像生成AIを使っていると、この一言が地味に怖い。

 

猫だけ直してくれと頼んだのに、背景が変わる。

 

背景だけ直したかったのに、人の顔が変わる。

 

三回修正した頃には、最初に気に入っていた画像がどこかへ行っている。

 

GPT Image 2.5でOpenAIが正面から改善対象にしてきたのが、まさにこの問題だった。

 

参照画像の被写体をより維持し、複数回の編集でも指示へ安定して従い、設定・スタイル・構図を変えながら元画像の細部をより残す。

 

つまり今回の進化は、

 

「もっと凄い一枚を出す」だけではなく、「気に入った一枚を壊さず育てる」方向へ踏み込んだ。

 

ここが本題である。

 

📜 第一章　画像AI、「一発ガチャ」から抜け出したくなる

画像生成AIには昔から、妙な強さと妙な弱さが同居していた。

 

ゼロから一枚作らせると、とんでもないものが出る。

 

ところが、

 

「いいね。そのまま右の人物だけ消して」

 

となった瞬間、話が変わる。

 

頼んでいない場所まで変化することがある。

 

ユーザーからすると、

 

そこは気に入ってたから触るな。

 

という話なのだが、画像生成モデルにとって「画像の一部分だけを変更し、残りを完全に維持する」という仕事は、単純な新規生成とは違う難しさがある。

 

ChatGPT Images 2.5についてOpenAIが強調している改善点の一つが、参照写真に含まれる被写体の保持だ。

 

さらに、複数ターンにわたる編集指示への追従も改善したとしている。

 

OpenAIのSystem Cardでも、画像の設定、スタイル、構図を変更しながら、より多くのディテールを保持できるようになったと説明されている。インフォグラフィックの正確性やレイアウトについても改善が報告されている。

 

これ、画像生成AIをあまり使わない人には小さな改良に見えるかもしれない。

 

逆である。

 

画像を何度も作る人ほど、

 

「最初から作り直さなくていい」

 

の価値が大きい。

 

一発目が70点だったとする。

 

従来なら「もう一回生成」で80点を狙った結果、顔は90点になったのに構図が50点になることがある。

 

また生成する。

 

今度は構図85点、顔70点、背景60点。

 

いつ完成するんだこれ。

 

町内会の議題を一個直すたびに規約全文を書き直しているような状態である。

 

GPT Image 2.5が狙っているのは、そのゲームそのものを変えることだ。

 

70点の画像ができたら、

 

「ここを直す」

 

「次はここ」

 

「ここは残す」

 

と積み上げて完成へ近づける。

 

画像AIが完成品を一発で吐く機械から、修正を重ねられる制作道具へ寄ってきたのである。

 

📜 第二章　2.5なのに一人じゃない　FlareとSunburstに分裂する

そしてGPT Image 2.5には、もう一つ分かりにくい点がある。

 

APIでは「GPT Image 2.5」という一枚岩のモデルだけが置かれているわけではない。

 

GPT-Image-2.5 Flare

 

そして、

 

GPT-Image-2.5 Sunburst

 

の二系統が用意された。

 

Flareは、日常的な高品質画像生成を高速に行うモデルとして位置づけられている。

 

OpenAIのAPI資料では、Flareを高品質な日常画像生成向けの最速モデルとして説明している。テキストだけでなく画像も入力でき、画像を出力できる。

 

対するSunburstは、画像生成と編集でOpenAIの最も高性能なモデルとして位置づけられ、特に編集精度が重要なワークフロー向けとされる。

 

つまり、

 

Flare「早く回そう」

 

Sunburst「細かく詰めよう」

 

である。

 

もちろん「Flare＝雑、Sunburst＝上位互換」と単純化するのは違う。

 

OpenAI自身、Flareには品質・編集・速度の改善を持たせ、Sunburstにはより詳細な制作作業のための追加的な精度を持たせると説明している。Sunburstはその分、生成時間が長くなる。

 

ここで画像生成の使い方が変わってくる。

 

大量に案を出したい。

 

まず構図を探したい。

 

何パターンも比較したい。

 

そういう場面なら速度が効く。

 

一方、

 

「この人物は維持」

 

「この小物だけ変更」

 

「この構図を崩したくない」

 

となれば、精密な編集能力が効いてくる。

 

最強モデルを一個選んで終わり、ではなくなった。

 

制作工程のどこにいるかで道具を選ぶ設計になっている。

 

しかもFlareとSunburstは、low、medium、highに加えて、xhigh、max、autoの品質設定にも対応する。

 

モデルを選ぶ。

 

さらに品質を選ぶ。

 

画像AI側が「全部最高品質で一発勝負」から離れ、制作工程に合わせて調整する道具になってきたわけだ。

 

🧩 つまり、どういうこと？

GPT Image 2.5を見る時、覚えておきたいのは一つ。

 

進化したのは「一枚の絵」だけではなく、「一枚を完成まで持っていく過程」だ。

 

生成速度を上げるFlare。

 

編集精度を重視するSunburst。

 

そして複数回編集で元画像を維持しやすくするImages 2.5。

 

一発で神画像を引くまでガチャを回す世界から、気に入った画像へ修正を積み上げる世界へ少しずつ移動している。

 

📜 第三章　ついに「文章で全部説明しろ」まで崩し始めた

そして今回、モデルそのものと同じくらい見逃しにくいのがChatGPT側の変化である。

 

Sketchが入った。

 

ChatGPT上で簡単な絵を描き、それを完成画像の参照として使える。

 

これは地味に画像生成AIの根本問題へ刺さっている。

 

たとえば、

 

「猫を画面左下に置いて、その奥にテーブル、右側に人物。人物より猫を少し手前にして……」

 

と文章で説明する。

 

面倒である。

 

紙なら3秒で描ける。

 

○　←人

 

□　←机

 

🐈　←ここ

 

極端に言えば、それで済む。

 

人間は視覚的な配置を必ずしも文章で考えていないのに、画像生成AIを使うために一度文章へ翻訳していた。

 

Sketchは、その翻訳作業を一部飛ばせる。

 

さらにChatGPT Images 2.5では、画像へ直接コメントを置き、変更したい場所を指定する編集方法も導入された。テンプレートから制作を始めたり、使用したプロンプトを他人と共有したりする機能も加わっている。

 

これも方向は同じだ。

 

「完璧なプロンプトを書け」

 

から、

 

「見せろ。指せ。直せ。」

 

へ寄っている。

 

画像AIなのに、画像を作るための入口が長文プロンプトだけではなくなってきた。

 

これは結構大きい。

 

GPT Image 2.5の記事を読んでいた画像AI好き三人。

 

画質の話をすると思ったら、全員なぜか「修正で壊れる問題」に食いついた。

🪭 史料から見える、意外な素顔

① 「高画質化」が主役に見えて、実際は編集工程の改善がかなり大きい

OpenAIの発表文には、鮮明さ、照明、質感といった分かりやすい画質改善も並んでいる。

 

しかし同じ発表で繰り返し強調されているのが、参照被写体の保持と複数ターン編集である。

 

System Cardでも編集時の一貫性改善が独立した特徴として扱われている。

 

画像AIの性能競争が、「最初に何を出せるか」だけでは測りにくくなっていることが分かる。

 

二枚目、三枚目、四枚目の修正で何を残せるか。

 

完成まで使うなら、むしろそこが効く。

 

② 高性能モデルを一個置くのではなく、制作速度と精密さを分けた

FlareとSunburstという二モデル構成も象徴的だ。

 

Flareは高速な日常生成。

 

Sunburstは精密な画像生成・編集。

 

「新型だから全員これを使え」ではなく、何をしている最中なのかでモデルを選ぶ方向になった。

 

ラフ案を50枚見たい人と、一枚の人物写真を何度も直したい人では欲しい性能が違う。

 

考えてみれば当たり前なのだが、画像AIもようやく工具箱っぽくなってきた。

 

③ それでも「指定箇所以外は絶対不変」になったわけではない

ここはかなり重要だ。

 

公式資料が述べているのは、保持能力や編集指示への追従が改善したということ。

 

「一ピクセルも変わらない」「人物が絶対に別人にならない」という保証ではない。

 

AI画像編集である以上、出力には変動があり得る。

 

だからGPT Image 2.5を、

 

「Photoshopのレイヤー編集と完全に同じになった」

 

とまで言ってしまうと飛躍する。

 

進んだ。

 

だが魔法にはなっていない。

 

この距離感が一番正確だ。

 

🌱 その後の画像生成に残りそうなもの

まず一つ目は、反復速度そのものが性能になるという考え方だ。

 

Images 2.5ではImages 2.0比で生成レイテンシーが最大50％短縮されたとOpenAIは説明している。

 

画像一枚の待ち時間だけ見れば数十秒の差でも、一日に何十回、何百回と試す制作では意味が変わる。

 

「一枚を待つ時間」ではなく「一時間で何回試せるか」の話になる。

 

二つ目は、画像の一貫性が制作性能として前面に出たこと。

 

キャラクター、商品、人物、構図などを維持しながら変更する能力が上がれば、画像AIは単発のネタ画像だけでなく、連作や広告素材、商品写真、漫画、デザイン検討にも使いやすくなる。OpenAIも商品体験やクリエイティブワークを利用例として挙げている。

 

三つ目は、プロンプト以外の操作方法が増えたこと。

 

Sketch、テンプレート、画像上コメント。

 

人間側がAIの都合に合わせて全部文章へ翻訳するのではなく、AI側が人間の「ここ」「こんな配置」という伝え方へ寄ってきた。

 

ここは今後かなり重要になりそうだ。

🐾 猫じろうの歴史ちょこっと授業

レイテンシー

命令してから結果が返ってくるまでの遅延時間。

 

Images 2.5についてOpenAIが「最大50％短縮」としているのは、この生成レイテンシーだ。料金が50％安くなったという意味ではない。

 

xhigh / max

GPT-Image-2.5 FlareとSunburstでは、従来からあるlow、medium、highだけでなく、xhighとmaxも品質設定として利用できる。

 

ただし、名前だけを見て「常にmaxが最適」と考える必要はない。

 

試行段階では速度、完成工程では品質という使い分けもあり得る。

 

Image APIとResponses API

GPT-Image-2.5系は、開発者がAPIから画像生成へ利用できる。

 

FlareとSunburstはImage APIで直接モデルを指定でき、Responses APIの画像生成でも利用できる。

 

ChatGPT Images 2.5とAPIモデル名は同じではない

ここは検索すると混乱しやすい。

 

ChatGPTで提供される体験はChatGPT Images 2.5。

 

開発者向けAPIではGPT-Image-2.5 FlareとGPT-Image-2.5 Sunburstというモデル名が使われる。

 

「GPT Image 2.5」という言葉だけで全部を一括りにすると、ChatGPTの機能とAPIのモデル仕様が混ざりやすい。

 

🔎 ここ、よく勘違いされる

「最大50％高速になった」

 

これを、

 

「半額になった」

 

と読み替えてはいけない。

 

SunburstのAPI資料では、画像出力トークンなどの料金レートはGPT Image 2と同水準とされている一方、GPT Image 2用の計算機では2.5のトークン消費量を推定できないと明記されている。

 

速度と料金は別の話である。

 

もう一つ。

 

OpenAIは、ChatGPT ImagesとAPIのGPT-Imageモデルを合わせて毎週30億枚以上の画像が作られているとしている。

 

これは「GPT Image 2.5だけで週30億枚」ではない。

 

発表直後のモデルに、いきなり全人類が30億枚突っ込んだわけではない。

 

GPT Image 2.5で覚えておくなら三つでいい。

 

一発生成だけでなく、複数回の編集で画像を維持する方向が強化された。

 

APIでは高速なFlareと、精密編集寄りのSunburstに分かれた。

 

Sketchや画像上コメントによって、画像を作るために何もかも文章で説明する必要まで減らし始めた。

 

画像AIの進化を「去年より綺麗」で見ていると、この変化は少し見落としやすい。

 

今回は絵だけではなく、絵との付き合い方そのものを直しに来た更新だった。
